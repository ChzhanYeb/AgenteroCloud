# BALROG: Benchmarking Agentic LLM and VLM Reasoning On Games

> 大型语言模型（LLM）和视觉语言模型（VLM）拥有广泛的知识并展现出令人瞩目的推理能力，但它们在复杂、动态的环境中仍难以发挥良好表现。现实世界的任务需要处理错综复杂的交互、高级空间推理、长期规划以及对新策略的持续探索——在这些领域，我们缺乏有效的方法来全面评估这些能力。为了弥补这一空白，我们提出了 BALROG，一个新颖的基准测试，旨在通过一系列多样化且富有挑战性的游戏来评估 LLM 和 VLM 的智能体能力。我们的基准测试整合了多种难度级别的现有强化学习环境，涵盖了从非专业人类几秒内即可解决的任务，到可能需要数年才能掌握的极具挑战性的任务（例如 NetHack 学习环境）。我们设计了细粒度指标来衡量性能，并对多个流行的开源和闭源 LLM 及 VLM 进行了广泛评估。研究结果表明，当前模型在较简单的游戏中能够取得部分成功，但在更具挑战性的任务中则表现显著不佳。值得注意的是，我们观察到基于视觉的决策存在严重缺陷，因为多个模型在提供环境视觉表征时表现反而变差。我们将 BALROG 作为一个开放且易于使用的基准测试发布，以促进智能体社区未来的研究与发展。代码和排行榜见 https://balrogai.com。

## 一句话定位

BALROG 把 6 个强化学习游戏环境（BabyAI / Crafter / TextWorld / Baba Is AI / MiniHack / NLE）装进同一个"自然语言动作"接口，用**每环境 0–100 的归一化进度分 + 跨环境等权平均**做排行榜，并把"语言模态 vs 视觉模态"当成受控变量来测，结论是当前模型在长时程游戏上几乎全线失败、且**加上图像往往更差** [§3.1](papers/Agent规划/2411.13543/2411.13543.pdf) [§4](papers/Agent规划/2411.13543/2411.13543.pdf)。

## 问题与动机

**痛点一：现有 agent benchmark 的时程太短。** 论文开篇就把靶子立得很清楚：当前 agentic benchmark 的交互轮数"不超过几十轮"——办公任务（OfficeBench）、网页导航（WebArena）、修 GitHub issue（SWE-bench）都是这个量级；而真实任务需要数量级更多的交互 [§1](papers/Agent规划/2411.13543/2411.13543.pdf)。BALROG 的 6 个环境按"完成所需轮数"从 $10^1$ 铺到 $10^4$–$10^5$，人类掌握时间从秒到年 [Table 1](papers/Agent规划/2411.13543/2411.13543.pdf)。这是**时程维度上的补位**，不是又一个任务集合。

**痛点二：短时程 benchmark 正在饱和，且饱和后无法分辨能力。** 论文指出新 prompting 框架与 o1 类模型让 SOTA 在这些 benchmark 上快速上涨 [§1](papers/Agent规划/2411.13543/2411.13543.pdf)；相关工作里更直接地说某些既有游戏 benchmark "已经接近饱和，Crafter 已经是它们中最难的" [§5](papers/Agent规划/2411.13543/2411.13543.pdf)。因此需要一个**连专用神经模型都只能取得有限进展**的难度上界，NetHack 就是那个上界。

**痛点三：视觉决策几乎没被系统测过。** 多数环境本来就是为视觉设计的，但 LLM agent benchmark 普遍只喂文本。"给不给图像"这件事在文献里通常是实现细节，BALROG 把它提升为**实验因子**，同一模型跑两种模态再比较 [§3.2](papers/Agent规划/2411.13543/2411.13543.pdf)。

**痛点四：防记忆污染。** 所有环境都是程序化生成的，"同一个环境实例遇到两次都不太可能"，因此无法靠记住测试集刷分 [§1](papers/Agent规划/2411.13543/2411.13543.pdf)。这一点与"确定性可重放"是有张力的——见后文局限一节。

## 方法与机制

### 架构：把"策略"和"模型"解耦

框架的显式设计目标是让 **inference-time prompting strategy 与底层模型解耦**，目的有二：便于快速试新的推理期方法；保证模型间比较一致 [§2](papers/Agent规划/2411.13543/2411.13543.pdf)。落到代码上是四个接缝 [Figure 1](papers/Agent规划/2411.13543/2411.13543.pdf)：

- `client.py`：统一封装 OpenAI / Gemini / Claude API 与本地 vLLM 服务，换模型只改配置；
- `agent.py`：prompt builder 负责观测历史管理与动作解析，**新策略只需改这一个文件**；
- `env_wrapper.py`：把 6 个异构环境标准化成同一套 `reset / step` 语义；
- evaluator：异步并行跑多个 agent 与环境实例，收集指标。

这个分层值得单独强调：它使"模型能力"与"脚手架能力"在提交协议上可分——leaderboard 接受两类提交，**New Models**（默认 zero-shot 评测）与 **Agentic Strategies**（推理期策略，须超出单纯 zero-shot 直接预测动作）[§2.2](papers/Agent规划/2411.13543/2411.13543.pdf)。

### 统一接口：动作是自然语言字符串

每个时间步，Agent 以"过去交互历史"为条件，输出**下一条动作的自然语言字符串** [§3.1](papers/Agent规划/2411.13543/2411.13543.pdf)。合法性由环境侧判定，非法时：

1. 向 Agent 返回"该动作非法"的反馈；
2. 执行一个**默认兜底动作**（`do-nothing` 或标准移动如 `north`）；
3. 记录该事件，供事后统计非法动作的上下文与频次 [§3.1](papers/Agent规划/2411.13543/2411.13543.pdf)。

这一条是全部工程细节里对分数影响最大的：**评测不会因格式错误而中断**（对比之下 AgentBoard 也是返回错误但继续），但兜底动作会真实改变状态，于是分数里混入了"格式遵从能力"。

动作空间大小因环境而异且**在 prompt 里显式列出**：BabyAI 只有 6 个（turn left / turn right / go forward / pick up / drop / toggle）[§A](papers/Agent规划/2411.13543/2411.13543.pdf)，Crafter 17 个 [§B](papers/Agent规划/2411.13543/2411.13543.pdf)，TextWorld 是命令文法（`go <dir>`、`take ... from ...`、`cook ... with ...`）[§C](papers/Agent规划/2411.13543/2411.13543.pdf)，NetHack 与 MiniHack 是数十个动词加方向/物品补全（`north` … `far northwest`、`apply`、`zap`、`travel` 等）[§F](papers/Agent规划/2411.13543/2411.13543.pdf)。

### 观测：两种模态 + 一个固定的历史窗

除 TextWorld（本身无视觉）外，每个环境都跑两种观测模态 [§3.2](papers/Agent规划/2411.13543/2411.13543.pdf)：

- **Language only**：环境状态的文字描述（如 "a wall 5 steps forward, a wall 2 steps left…"）。无原生文本表示的环境用现成 wrapper（BabyAI、Crafter、NetHack、MiniHack）或自建 wrapper（Baba Is AI）。
- **Vision-Language**：**当前步**的图像 + 同一段文字描述。图像只对应当前观测，历史部分仍以文本给出。

MiniHack 与 NetHack 额外附 ASCII 字符地图；所有实验统一使用 **16 条观测**的历史长度 [§3.2](papers/Agent规划/2411.13543/2411.13543.pdf)。prompt 是从"user"视角给规则与观测、从"assistant"视角给历史动作的 chat 格式，且**不针对任何具体模型微调 prompt**，以防过拟合到某个模型 [§3.2](papers/Agent规划/2411.13543/2411.13543.pdf)。NetHack 上还做了上下文瘦身：只长期保留 game message 与 language observation，stats/inventory 只留当前步，以防上下文爆炸 [§F](papers/Agent规划/2411.13543/2411.13543.pdf)。

### 指标：0–100 的归一化进度

**单个任务的分数定义**（[§3.1](papers/Agent规划/2411.13543/2411.13543.pdf)）：把每个任务的性能映射到 $[0,100]$，分三类：

| 计分类型 | 适用环境 | 定义 | 隐含粒度 |
|---|---|---|---|
| 二值完成 | MiniHack、BabyAI、Baba Is AI | 完成 $=100$，否则 $=0$ | 一个任务只有 1 bit |
| 成就比例 | TextWorld、Crafter | 已达成成就 / 最大成就数 $\times 100$ | 由成就总数决定 |
| 数据驱动进度 | NetHack (NLE) | 见下式 | 连续 |

**NetHack 的进度函数**是本文唯一真正"新设计"的指标 [§F](papers/Agent规划/2411.13543/2411.13543.pdf)。作者认为游戏内建分数不能反映真实进展（通关分数可从几十万到几百万），于是用人类对局数据集统计"到达某地牢层/某经验层后最终获胜的条件概率"，构造两条生存曲线，并把刻度固定为：

$$P_{\text{NLE}}(s_t)=\max\Big(\,g_{\text{dlvl}}(\text{dlvl}_t),\; g_{\text{xl}}(\text{xl}_t)\,\Big)\times 100,\qquad g(1)=0,\ g(\text{ascension})=1$$

$g_{\text{dlvl}}$、$g_{\text{xl}}$ 分别是按地牢层与经验层统计的人类获胜概率（单调化后的曲线），取两者最大值作为该步进度，保证"下得更深"或"练得更强"任一条线推进都算进展。**这是整篇论文里唯一带"Oracle 味道"的设计**：它用外部人类数据把稀疏的终局信号转成稠密标量，而不是靠人工切 subgoal。

**跨环境聚合**：主表报的是跨环境平均。这个平均是**等权**的，可以由分项表直接复算验证——GPT-4o 语言模态：$77.60$（BabyAI）$+33.10$（Crafter）$+39.31$（TextWorld）$+33.66$（Baba Is AI）$+10.00$（MiniHack）$+0.37$（NLE）$=194.04$，$/6=32.34$，与表中的 $32.34\pm1.49$ 一致 [§4](papers/Agent规划/2411.13543/2411.13543.pdf) [§A](papers/Agent规划/2411.13543/2411.13543.pdf) [§B](papers/Agent规划/2411.13543/2411.13543.pdf) [§C](papers/Agent规划/2411.13543/2411.13543.pdf) [§D](papers/Agent规划/2411.13543/2411.13543.pdf) [§E](papers/Agent规划/2411.13543/2411.13543.pdf) [§F](papers/Agent规划/2411.13543/2411.13543.pdf)。视觉模态没有 TextWorld，因此是**5 环境等权**：Claude 3.5 Sonnet $82.00+37.27+34.45+22.50+1.16=177.38$，$/5=35.48$，与表中一致。正文没有明写加权方式，但算术上唯一自洽的解释就是等权。

### 评测循环

```mermaid
flowchart TD
    A[环境 reset: 规则 + 动作清单 + 首帧观测] --> B[agent.py 组装 prompt:<br/>规则 / 动作表 / 16 条历史]
    B --> C[client.py 调用 LLM 或 VLM]
    C --> D[解析出自然语言动作 a_t]
    D --> E{动作合法?}
    E -- 否 --> F[回传非法提示 + 执行兜底动作<br/>并记录事件]
    E -- 是 --> G[env_wrapper.step 执行]
    G --> H[观测 o_t: 文本 (+图像) (+ASCII 图)]
    F --> H
    H --> I[更新历史窗口]
    I --> J{episode 结束?}
    J -- 否 --> B
    J -- 是 --> K[按环境计分 0-100]
    K --> L[多 seed 平均 → 跨环境等权平均]
```

seed 数按环境不同：BabyAI 25、Crafter 10、TextWorld 20、Baba Is AI 5、MiniHack 5、NLE 5 [§A](papers/Agent规划/2411.13543/2411.13543.pdf) [§B](papers/Agent规划/2411.13543/2411.13543.pdf) [§C](papers/Agent规划/2411.13543/2411.13543.pdf) [§D](papers/Agent规划/2411.13543/2411.13543.pdf) [§E](papers/Agent规划/2411.13543/2411.13543.pdf) [§F](papers/Agent规划/2411.13543/2411.13543.pdf)。这个不均匀本身会影响标准误的可比性。

## 实验设置与关键结果

模型覆盖闭源与开源：Gemini-1.5-Flash/Pro、GPT-4o-mini（2024-07-18）、GPT-4o（2024-05-13）、Claude 3.5 Sonnet/Haiku（2024-10-22）、Llama 3.1 instruct（8B/70B）、Llama 3.2 instruct（1B/3B/11B/90B），外加**仅在 NetHack 上跑**的 o1-preview（预算限制），全部 zero-shot [§3.3](papers/Agent规划/2411.13543/2411.13543.pdf)。

**语言模态总榜**（Average Progress %）：

| 模型 | 平均 | 模型 | 平均 |
|---|---|---|---|
| claude-3.5-sonnet | **32.64 ± 1.93** | gpt-4o-mini | 17.36 ± 1.35 |
| gpt-4o | 32.34 ± 1.49 | llama-3.2-11B-it | 16.82 ± 1.47 |
| llama-3.1-70b-it | 27.88 ± 1.43 | llama-3.1-8b-it | 15.14 ± 1.55 |
| llama-3.2-90B-it | 27.29 ± 1.44 | gemini-1.5-flash | 14.63 ± 1.37 |
| gemini-1.5-pro | 21.00 ± 1.18 | llama-3.2-3B-it | 10.13 ± 1.28 |
| claude-3.5-haiku | 19.32 ± 1.83 | llama-3.2-1B-it | 6.65 ± 1.04 |

**视觉模态总榜**：claude-3.5-sonnet $35.48\pm2.02$ > gemini-1.5-pro $25.76\pm1.36$ > gpt-4o $22.56\pm1.44$ > llama-3.2-90B $20.99\pm1.58$ > gpt-4o-mini $15.36\pm1.29$ > gemini-1.5-flash $14.94\pm1.40$ > llama-3.2-11B $8.43\pm1.26$ [§4](papers/Agent规划/2411.13543/2411.13543.pdf)。**排名第一不变，但 GPT-4o 从 32.34 掉到 22.56、Llama 3.2 90B 从 27.29 掉到 20.99、11B 从 16.82 掉到 8.43，而 Claude Sonnet 从 32.64 升到 35.48、Gemini Pro 从 21.00 升到 25.76**——不是"VLM 普遍更差"，而是"VLM 对视觉输入的利用能力高度分化"。

**分环境最好成绩**（语言模态）：

| 环境 | 最佳模型 | 分数 |
|---|---|---|
| BabyAI | gpt-4o | 77.60 ± 3.73（llama-3.1-70b 73.20） |
| Crafter | gpt-4o | 33.10 ± 2.32（sonnet 32.73） |
| TextWorld | claude-3.5-sonnet | 42.06 ± 5.41（gpt-4o 39.31；Gemini 两个型号记 0） |
| Baba Is AI | llama-3.2-90B | 43.90 ± 3.47（胜 GPT-4o 约 10 个点） |
| MiniHack | claude-3.5-sonnet | 15.00 ± 5.65（gpt-4o、haiku、4o-mini 并列 10.00） |
| NLE | o1-preview | 1.57 ± 0.40（次优 claude-3.5-haiku 1.16） |

**归因分析（论文自己做的三个对照）**：

1. **视觉输入是负向因子（对部分模型）**。同模型两模态对比已如上；Crafter 上还做了"换渲染风格"的对照——把 2D 瓦片换成 Minecraft 风格 3D 渲染，**结果没有变好反而更差**：Claude Sonnet $37.27\to25.45$、Gemini Pro $33.50\to30.45$、GPT-4o $26.81\to24.55$、Llama 3.2 90B $10.00\to12.27$（这一项反向）[§B](papers/Agent规划/2411.13543/2411.13543.pdf)。作者据此否定"纹理分布外（OOD）导致 VLM 失效"的假说，把原因指向空间推理与任务适配而非视觉熟悉度 [§B](papers/Agent规划/2411.13543/2411.13543.pdf)。**注意这里有一处可在原文核到的内部不一致**：Crafter 主表的视觉分与渲染对照表的"2d textures"列对不上（Llama 3.2 90B 主表 $14.54$ vs 对照表 $10.00$；11B 主表 $15.91$ vs 对照表 $23.63$），两组实验的 seed 或任务集合显然不同，但正文未说明差异来源。

2. **推理期算力能改善但不足以翻盘**。o1-preview 在 NLE 上是 $1.57\%$，约为次优 Claude 3.5 Sonnet（$0.58\%$）的 2.7 倍——正文与附录分别写作"接近三倍"和表内 $\pm0.40$ vs $\pm0.52$ 的置信区间 [§4.1](papers/Agent规划/2411.13543/2411.13543.pdf) [§F](papers/Agent规划/2411.13543/2411.13543.pdf)。单局最好成绩来自 Gemini-1.5-Pro 视觉模态，到达地牢第 3 层、经验第 4 级 [§F](papers/Agent规划/2411.13543/2411.13543.pdf)。

3. **"知道"与"做到"解耦**。用 5 道 NetHack 知识题（吃腐食、吃过量、从第 1 层上楼、对怪物用隐身、向愤怒的神祈祷）分别评"回答是否正确 / 结论是否正确 / 实际行为是否避免"，结果模型普遍能给出正确结论，但行为常常相反——GPT-4o 在 Q1（腐食）与 Q3（上楼自杀）上"结论正确、行为错误" [§F](papers/Agent规划/2411.13543/2411.13543.pdf)。这是论文最有价值的一张诊断表。

**定性失败模式**（[§4.1](papers/Agent规划/2411.13543/2411.13543.pdf)）：空间推理差（BabyAI 里无法把物体放到另一物体旁；CorridorBattle 里常被逼进角落）；探索无系统性（Coin Collector 里在已探索房间反复打转，不会像 DFS 那样记账）；长期规划近乎为零（MiniHack 的 Boxoban 逻辑推箱**没有任何一次成功轨迹**，因为每一步都可能造成不可逆失败）；不会推断环境动力学（想不起用 `wand of cold` 或 `ring of levitation` 过熔岩河；Crafter 里会砍树造工具但不会造庇护所过夜）。

## 阅读重点

### 1. 多游戏环境如何统一接口和报告？

**接口层**统一在三件事上，而不是统一在"动作空间"上。(a) **动作表示**：所有环境的动作都被压成"自然语言字符串"，由各环境自己的 parser 翻译回离散动作（例如 NLE 的 `north` 映射到对应 key）[§3.1](papers/Agent规划/2411.13543/2411.13543.pdf) [§F](papers/Agent规划/2411.13543/2411.13543.pdf)。(b) **观测表示**：统一成"文本描述（+可选图像）"，无原生文本的环境靠 wrapper 生成，Baba Is AI 因为要解析规则块还专门写了自定义 wrapper [§D](papers/Agent规划/2411.13543/2411.13543.pdf)。(c) **控制流**：统一的 `reset/step`、统一的非法动作处理（反馈 + 兜底 + 记录）、统一的历史长度 16 [§3.1](papers/Agent规划/2411.13543/2411.13543.pdf) [§3.2](papers/Agent规划/2411.13543/2411.13543.pdf)。

**报告层**统一在"每任务 0–100 + 跨环境等权平均 + 多 seed 标准误"。这里有两个必须点明的取舍：其一，**动作空间并没有统一**（BabyAI 6 个 vs NetHack 数十个动词加补全），所以"同一条 prompt 模板"在不同环境里承担的信息负荷差别很大；其二，**等权平均把 6 个环境视作等价**，而它们的时程差三个数量级——这等于让 NLE（几乎所有模型 $\le1.6$）在总分里占 1/6 的固定权重，其效果是把所有人的总分压缩到 100 以下很远的地方（实际最高 35.48），**总分的绝对值因此不具"完成度"含义**。

### 2. Progress / Score 的归一化方式是什么？

三层归一化，越往下越依赖外部假设：

1. **单任务到 $[0,100]$**：二值任务（MiniHack / BabyAI / Baba Is AI）用 $100\cdot\mathbf{1}[\text{solved}]$；成就型任务（TextWorld / Crafter）用 $100\times(\text{已达成成就}/\text{最大成就数})$；NLE 用 $100\times P_{\text{NLE}}(s_T)$，其中 $P_{\text{NLE}}$ 是"人类在该地牢层/经验层最终通关的条件概率"，并强制 $g(1)=0$、$g(\text{ascension})=1$，取两条轴的最大值 [§3.1](papers/Agent规划/2411.13543/2411.13543.pdf) [§F](papers/Agent规划/2411.13543/2411.13543.pdf)。
2. **episode 到 seed 平均**：每环境多 seed 取均值与标准误，seed 数 5–25 不等。
3. **环境到总分**：等权算术平均（语言模态 6 项、视觉模态 5 项），可由分项表复算。

归一化的代价要说清楚：**二值任务让"细粒度"名不副实**。MiniHack 的分项值全部是 2.5 的整数倍（$15.00/10.00/7.50/5.00/2.50$），暗示其底层是约 40 个 episode 的二值平均；也就是说 MiniHack 这个"最难的子集"在分数上只有 40 个离散台阶，且每个台阶是 2.5。任务是 5 个还是 8 个（附录列出 Maze 9x9 与 15x15 两种 Maze）未能从原文完全对齐，**具体 episode 构成未能核实**。相对地，TextWorld 与 Crafter 的比例分更连续，NLE 的曲线分最连续——但 NLE 的曲线直接继承人类对局分布，**它度量的是"像不像人类推进"，不是"最优不最优"**。

### 3. 视觉观察、工具交互和游戏策略分别带来什么困难？

**视觉观察**：核心发现不是"VLM 差"，而是"VLM 不知道该怎么用图"。同模型两模态对比出现双向分化（GPT-4o $-9.8$、Llama 90B $-6.3$、Llama 11B $-8.4$ 个点，而 Claude Sonnet $+2.8$、Gemini Pro $+4.8$ 个点）[§4](papers/Agent规划/2411.13543/2411.13543.pdf)。论文用 3D 渲染对照排除了"纹理 OOD"解释，把矛头指向"训练目标是图像描述而非动作导向推理""网格图像偏离自然图文对""空间推理不足" [§B](papers/Agent规划/2411.13543/2411.13543.pdf) [§6](papers/Agent规划/2411.13543/2411.13543.pdf)。还有一个常被忽略的工程限制：受图像处理成本所限，**每个观测只放一张当前帧**，历史全是文本 [§6](papers/Agent规划/2411.13543/2411.13543.pdf)——这意味着"VLM 在视觉决策上失败"的结论至少部分被这个限制中介，作者自己承认了这一点。

**工具交互**：这里的"工具"是游戏内物件与菜单式交互，难点全在**格式精度**。NLE 的交互是终端式的：`What do you want to eat? [dgh or ?*]` 要求回答单个字母，`In what direction?` 要求回答方向，消息以 `--More--` 结尾时下一步必须先 `more`，否则会卡住 [§F](papers/Agent规划/2411.13543/2411.13543.pdf)。这类约束在 prompt 的 Tips 里被逐条写出，但仍然构成长尾失败源；而非法动作会被兜底成 `north` 或 `wait`，于是**"格式错误"被转化为"角色乱走"**，两种失败在最终分数上不可区分 [§3.1](papers/Agent规划/2411.13543/2411.13543.pdf)。这正是 BalatroEval 必须避免的混淆。

**游戏策略**：四类能力缺口的证据强度不同。空间推理与探索的证据是定性的（角落被围、房间重复访问）[§4.1](papers/Agent规划/2411.13543/2411.13543.pdf)；长期规划的证据是硬的——Boxoban 零成功、MiniHack 全体 $\le22.5$、NLE 全体 $\le1.57$；环境动力学的证据是"有知识但不迁移"（知道 `wand of cold` 能冻熔岩却不使用）[§4.1](papers/Agent规划/2411.13543/2411.13543.pdf) [§E](papers/Agent规划/2411.13543/2411.13543.pdf)。三者叠加产生**误差累积**：每一步的小偏差都会改变后续状态分布，而 16 条历史窗口又不足以让模型回溯早期决策，于是长时程任务上的失败是结构性的而非采样噪声。

## 与 BalatroEval 的连接

BalatroEval 用 Balatro（扑克牌 Roguelike 构筑）测 LLM Agent 的决策能力，强调确定性可重放、动作集可枚举、可计算的局部 Oracle、Trace 为分析单位、控制搜索预算、区分估计型与可枚举型过程指标。BALROG 是这套设计**最重要的正面参照与反面参照各一半**：

| 维度 | BALROG | BalatroEval 的取舍 |
|---|---|---|
| 环境随机性 | 全部**程序化生成 + 随机**，明确以"防记忆污染"为目标 [§1](papers/Agent规划/2411.13543/2411.13543.pdf) | 需**固定种子可重放**：同一 seed 下轨迹可逐帧复现，才能做单步归因 |
| 动作可枚举性 | 动作表在 prompt 里列出，但 NLE/MiniHack 含补全参数，实际合法集依赖当前状态 | 每步动作集**完全可枚举**且可校验，非法动作应视为度量对象而非兜底 |
| 过程信号来源 | 终局二值 / 成就计数 / 人类生存曲线，**无逐步最优性判定** | 可计算局部 Oracle：给定 $s_t$ 与 $\mathcal{A}(s_t)$ 判定最优/可接受 |
| 分析单位 | 轨迹 + 定性失败模式 + 知识问卷 | 决策 Trace：Thought / Action / Observation / 状态快照 / 分数 |
| 预算控制 | 固定 16 条历史；zero-shot；未控制推理预算 | 显式控制搜索预算，保证不同策略可比 |
| 指标类型 | 归一化环境分（估计型：用人类分布当标尺） | 区分估计型过程指标与可枚举 Oracle 指标 |

可以直接继承的：

- **跨环境等权平均 + 多 seed 标准误**的报告骨架。BALROG 的总分被 NLE 这类"永远接近 0"的环境稀释，说明**聚合方式必须显式声明**；BalatroEval 若只有单一环境，可以改为按"底注/回合"分层的曲线，避免单一标量掩盖进展。
- **把模态当实验因子**的做法。BALROG 证明"加图可能更差"，这对 BalatroEval 是直接警示：Balatro 的界面是卡牌图像 + 数值文本，若只测纯文本会高估，若只测图像会低估，**必须两模态都跑**并分别报告。
- **非法动作的记录与事后分析**。BALROG 至少把非法动作事件单独记录 [§3.1](papers/Agent规划/2411.13543/2411.13543.pdf)，BalatroEval 应更进一步：Trace 里把"非法动作""合法但次优""Oracle 最优"分成三类标签。
- **外部数据驱动的稠密化**（NLE 生存曲线）。这是把稀疏终局信号变稠密的合法手段，且不依赖人工切 subgoal；但它是"人类分布标尺"而非"最优标尺"——正好是 BalatroEval 想用 Oracle 超越的那一类指标。

必须替换的：

- **确定性**。BALROG 靠随机化防污染，代价是无法做"同一局面不同动作"的反事实比较；BalatroEval 若要算每步 regret，必须在固定 seed 下重放，这与 BALROG 的设计目标相反。可以用"固定种子集合 + 跨种子聚合"同时拿到可重放与防过拟合。
- **即席兜底动作**。BALROG 的 fallback 会把格式失败伪装成策略失败；BalatroEval 应把非法动作直接判为该步失败并保留原始字符串，使"能不能生成合法动作"与"能不能选对动作"成为两个可分离指标。

## 局限与可批判点

**作者自述的局限**：论文**没有独立的 Limitations 章节**，末尾只有不编号的 Ethics Statement 与 Reproducibility Statement [§7](papers/Agent规划/2411.13543/2411.13543.pdf)。分散在讨论节的自述包括：视觉模态受"单帧图像 + 文本历史"限制；视频观测留待后续；few-shot/ICL 因单条 NetHack 示范可达 **70 万输入 token** 而在当前成本下不可行 [§6](papers/Agent规划/2411.13543/2411.13543.pdf)。

**我认为更值得追问的**：

1. **Gemini 的 0 分不是能力分**。TextWorld 上 Gemini 两个型号被记 0%，原因是 API 把输入判为 unsafe 而拒绝返回，作者自己说"提示里完全没有任何真实安全风险" [§C](papers/Agent规划/2411.13543/2411.13543.pdf)。这直接压低了 Gemini-1.5-Pro 的总分（21.00，若 TextWorld 按其 Crafter 水平 30 分计，总分将升到约 26），**跨模型排名因此被一个与能力无关的工程因素污染**。榜单里应把这格标为 N/A 而不是 0。
2. **二值计分与"细粒度"宣称冲突**。6 个环境里 3 个是 0/100，MiniHack 的分辨率约 2.5 分一档。论文标题强调 fine-grained，但真正细粒度的只有 Crafter、TextWorld 与 NLE。
3. **等权平均缺少依据**。时程跨三个数量级、能力覆盖面差很多，却给每个环境 1/6 权重；改一个字（例如把 MiniHack 的 5 个任务拆成 5 个环境）排名就会变。论文未做权重敏感性分析。
4. **zero-shot 单点设计混淆了"能力"与"策略"**。全部基线是 zero-shot 直接预测动作，没有 CoT、没有 self-refinement、没有 few-shot 基线（作者把后者列为未来工作）。因此"模型做不到"与"没人给它合适的推理脚手架"未被分离——而框架本身明明支持这类策略 [§2.2](papers/Agent规划/2411.13543/2411.13543.pdf)。
5. **knowing-doing gap 只有相关性证据**。5 题问卷显示"结论对、行为错"，但没有干预实验（例如把正确答案注入 prompt 看行为是否改变）。有趣的是附录提到模型"即使被提示也会吃过量致死" [§4.1](papers/Agent规划/2411.13543/2411.13543.pdf)，这其实是最接近干预的一条证据，却没有系统化。
6. **随机性 vs 可复现的张力**。程序化生成 + 多 seed 提高了抗污染性，但 5 个 seed（MiniHack、Baba Is AI、NLE）在 $10^4$ 步时程的任务上几乎不可能给出稳定估计；NLE 的标准误 $\pm0.40$ 相对于 $1.57$ 的均值已接近 25%。
7. **"stochastic" 与 RL 文献的对照缺失**。论文强调这些是 RL 环境、SOTA 仍是手写符号策略，但没有把 BALROG 分数与已发表的 RL agent 分数放在同一张表里，读者无法判断"1.57% 的 NLE 进度"在 RL 语境下有多差。

## 开放问题

- **步级信用分配**。论文自己指出 NetHack 需要准确的 credit assignment [§F](papers/Agent规划/2411.13543/2411.13543.pdf)，却只做了 episode 级评分。如何在没有局部 Oracle 的环境里近似出步级信号，是 BALROG 留下的最大空白——也正是 BalatroEval 用可枚举 Oracle 直接填的那个洞。
- **视觉历史**。单帧图像 + 文本历史是成本妥协；多帧或视频观测是否改变"加图更差"的结论，论文明确列为未来工作 [§6](papers/Agent规划/2411.13543/2411.13543.pdf)。
- **few-shot / ICL 的可行性边界**。单条 NetHack 示范 70 万 token，检索式 few-shot 是作者提出的绕行方案但未实验 [§6](papers/Agent规划/2411.13543/2411.13543.pdf)。
- **knowing-doing gap 的机制**。是知识未被检索、还是被检索但未进入决策？需要干预实验（提示注入、激活引导）而非问卷相关。
- **分数的可比性**。二值分、成就比例分、生存曲线分能否放在同一平均里？若不能，BALROG 的排行榜应该分环境排名而非总分排名。
- **难度校准**。$10^1$ 到 $10^5$ 的时程跨度是否应该用对数刻度聚合，而不是等权线性平均。
