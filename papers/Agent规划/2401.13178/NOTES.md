# AgentBoard: An Analytical Evaluation Board of Multi-turn LLM Agents

> 把 LLM 当作通用 Agent 来评测并不容易：要在统一框架下覆盖多样场景、保持部分可观测并支持多轮交互；而现有框架大多只看最终成功率，对过程几乎没有洞察。论文提出 AgentBoard：一个面向分析型评测的基准与开源框架，给出细粒度的进度率（progress rate）指标来刻画增量进展，并提供可做多角度分析的工具包，以提升 Agent 性能的可解释性。

## 一句话定位

AgentBoard 把「9 个多轮、部分可观测的文本环境」缝进同一个 POMDP 接口，并用**人工标注的 subgoal 序列**把二值的成功率换成 $[0,1]$ 上连续、单调不减的 progress rate，从而使"都失败了"的模型之间重新可比 [§2](papers/Agent规划/2401.13178/2401.13178.pdf) [§4.2](papers/Agent规划/2401.13178/2401.13178.pdf)。

## 问题与动机

**痛点一：成功率在困难环境上退化为常数。** 论文的核心论据是：在 AgentBench 这类困难环境中大多数模型成功率接近零，成功率作为排序信号已经失效，无法区分"差一点成功"和"几乎没动" [§1](papers/Agent规划/2401.13178/2401.13178.pdf)。这不是精度问题，而是**度量分辨率**问题——二值指标在低成功率区间没有梯度。

**痛点二：已有的细粒度奖励不可跨环境比较。** ALFWorld、ScienceWorld、BabyAI、Jericho 各自带有 reward/score，但定义与量纲各不相同（BabyAI 一个点、ScienceWorld 顺序 subgoal 100 分而 optional subgoal 1 分），拼在一起无法求平均 [§2.2](papers/Agent规划/2401.13178/2401.13178.pdf) [附录·ScienceWorld 重标注](papers/Agent规划/2401.13178/2401.13178.pdf)。论文对 ScienceWorld 原始计分的批评很具体：把"与橙汁在同一房间""把物质单独装在一个容器里"这类必要动作只记 1 分，而首个 sequential subgoal 离初始状态又很远，于是"已经做了很多正确动作"的模型仍只得极低分 [附录·ScienceWorld 重标注](papers/Agent规划/2401.13178/2401.13178.pdf)。

**痛点三：评测本身不统一。** 不同论文用不同 prompt、不同 agent 骨架（ReAct / Act / 各类模块化框架）、不同上下文超限处理方式，导致分数不可比 [§1](papers/Agent规划/2401.13178/2401.13178.pdf) [附录·Ablation Study](papers/Agent规划/2401.13178/2401.13178.pdf)。AgentBoard 的应对是**把 agent 骨架也固定成被评测对象的一部分**：统一一个极简 reflex agent（Act-only + one-shot 示例 + 滑动窗口记忆），把"框架差异"从混淆变量降级为控制变量 [§2.1](papers/Agent规划/2401.13178/2401.13178.pdf)。

与 AgentBench 的定位差异被明确写出：AgentBoard 的任务更"规划重"，其分数与传统推理/编码 benchmark 相关性高，而 AgentBench 的分数与知识型 MMLU 相关性高 [§2](papers/Agent规划/2401.13178/2401.13178.pdf)（此处引用的是 Ruan et al. 2024 的外部观察，不是本文实验）。

## 方法与机制

### 统一接口：一个确定性的 POMDP + 反馈函数

所有任务被写成五元组 $\langle g, \mathcal{S}, \mathcal{A}, \mathcal{O}, \mathcal{T}\rangle$：目标 $g$、状态空间、合法动作空间、观测空间（含环境反馈）、转移函数 $\mathcal{T}:\mathcal{S}\times\mathcal{A}\to\mathcal{S}$ [§2.1](papers/Agent规划/2401.13178/2401.13178.pdf)。轨迹概率写成

$$p_{\pi}(\tau) = p(s_0)\prod_{t=0}^{T}\pi(a_t \mid g, s_t, m_t)\,\mathcal{T}(s_{t+1}\mid s_t, a_t)$$

其中 $m_t=\{o_j,a_j,\dots,o_t\}$ 是记忆。关键工程约定是**所有环境的 $\mathcal{T}$ 都是确定性的**，随机性只来自模型采样 [§2.1](papers/Agent规划/2401.13178/2401.13178.pdf)——这一条对复现极其重要，也是后面"同一轨迹可重放"的前提。

反馈函数 $f$（注意与进度匹配函数同名但不同物）负责三类情形：查询式动作（如 *check valid actions*）返回全部合法动作；合法动作返回状态变化的文字描述；越界动作返回错误信息 [§2.1](papers/Agent规划/2401.13178/2401.13178.pdf)。这三类反馈合起来决定了**动作空间是否对 Agent 显式可枚举**——这一点直接决定了后面 Oracle 式指标能不能做。

### Progress Rate：把"走了多远"变成单调不减的标量

对每个交互轮 $t$ 定义进度 $r_t$，取值 $[0,1]$，初值 0，任务完成时为 1 [§2.2](papers/Agent规划/2401.13178/2401.13178.pdf)：

$$r_t=\begin{cases} r_t^{\text{match}}=\max\limits_{0\le i\le t} f(s_i,g), & f(\cdot,g)\ \text{连续}\\[2mm] r_t^{\text{subgoal}}=\max\limits_{0\le i\le t}\left(\dfrac{1}{K}\sum\limits_{k=1}^{K} f(s_i,g_k)\right), & \text{否则}\end{cases}$$

三个设计点值得单独拎出来：

1. **$\max$ 而不是当前值。** 进度一旦拿到就不回退，所以"走错路再走回来"不会被二次惩罚。论文明确说这是为了让偏离目标但仍取得过进展的 Agent 保留其已得分数（注释段落）[§2.2](papers/Agent规划/2401.13178/2401.13178.pdf)。代价是 $r_t$ 对"退化/绕圈"不敏感，只看最优点。
2. **两种实现对应两种可判定性。** 当状态与目标可直接比对时用 $f(\cdot,g)$（PDDL 的谓词集合、Sheet 的单元格）；当中间状态语义模糊（"打开冰箱"算不算进展）时，退化为 $K$ 个 subgoal 的平均命中率，$f(\cdot,g_k)\in\{0,1\}$ 由**正则表达式**匹配观测实现 [§2.2](papers/Agent规划/2401.13178/2401.13178.pdf) [附录·Alfworld 标注](papers/Agent规划/2401.13178/2401.13178.pdf)。
3. **成功率被定义为进度率的边界情形。** 任务统计表直接写 `Success Rate = (Progress Rate == 1)` [任务统计表](papers/Agent规划/2401.13178/2401.13178.pdf)。所以两者不是并列指标，而是一个包含另一个——这解释了为什么正文里算力不变、两列数字却系统性同向。

各任务的具体实例化（全部可追溯）：

| 任务 | 进度实现 | 匹配函数 |
|---|---|---|
| ALF / SW / BA / JC / TQ / TO-Todo | $r^{\text{subgoal}}$ | 正则匹配已标注的 necessary observation |
| PDDL | $r^{\text{match}}$ | $f=\dfrac{\lvert\mathcal{G}\cap\mathcal{P}\rvert}{\lvert\mathcal{G}\rvert}$，$\mathcal{G}$ 为目标谓词集，$\mathcal{P}$ 为当前谓词集 |
| WebShop | $r^{\text{match}}$ | 扩展原打分 $f=f_{\text{type}}\cdot\dfrac{\lvert\mathcal{U}_{\text{att}}\cap\mathcal{Y}_{\text{att}}\rvert+\lvert\mathcal{U}_{\text{opt}}\cap\mathcal{Y}_{\text{opt}}\rvert+\mathbf{1}[y_{\text{price}}\le u_{\text{price}}]}{\lvert\mathcal{U}_{\text{att}}\rvert+\lvert\mathcal{U}_{\text{opt}}\rvert+1}$，再对搜索页/商品页/下单页三个页面分取平均 |
| WebArena | $r^{\text{match}}$ | $r=\dfrac{n}{m+n}\big(r_d(r_q+r_p)\big)+\dfrac{m}{n+m}r_c$，$n=3$；$r_d$ 域名为 0/1，$r_q$ 用 LCS，$r_p$ 用 F1，$r_c$ 为必需内容命中率 |
| TO-Sheet | $r^{\text{match}}$ | 与 golden 表格同位单元格数值一致的比例 |

来源：[附录·Details of Progress Rate Metrics](papers/Agent规划/2401.13178/2401.13178.pdf)。注意 WebArena 的式子对 $m=0$（无必需内容任务）会退化为纯 URL 项，$n=3$ 时权重固定为 $3/(3+m)$。

### 一个可手算的例子

论文给的样例任务是 "clean an egg and put it in microwave"，标注的 subgoal 序列为：`open the fridge` → `taking an egg from the fridge` → `clean the egg with sinkbasin` → `put the egg in the microwave`，$K=4$ [§2.2](papers/Agent规划/2401.13178/2401.13178.pdf)。于是 $r_t^{\text{subgoal}}$ 只能取 $\{0,\ 0.25,\ 0.5,\ 0.75,\ 1\}$ 五个值。设轨迹为：

| 步 $t$ | 动作 | 命中的 subgoal | $r_t$ |
|---|---|---|---|
| 0 | `look` | 无 | 0 |
| 1 | `open fridge 1` | $g_1$ | 0.25 |
| 2 | `take egg 1 from fridge 1` | $g_2$ | 0.50 |
| 3 | `go to sinkbasin 1` | 无 | 0.50 |
| 4 | `clean egg 1 with sinkbasin 1` | $g_3$ | 0.75 |
| 5 | `go to microwave 1` | 无 | 0.75 |
| 6 | `heat egg 1 with microwave 1` | $g_4$ | **1.00** |

两点从这个例子直接读出来：(a) 第 3、5 步是**必要但不得分**的移动，进度率对这类"过程性动作"完全不奖励，所以 $r_t$ 与"动作效率"无关；(b) 若第 2 步失败（拿错物体），后续所有命中都不可能发生，$r_t$ 永久卡在 0.25——**早期单点失败会被放大成整条轨迹的低分**，这正是论文所说"初始小错难以挽回"的度量表现。反过来，$\max$ 保证第 3 步的绕路不会被扣分。

### 读数与口径：两个公式的变量含义

**WebShop**（[附录·WebShop 打分](papers/Agent规划/2401.13178/2401.13178.pdf)）：$\mathcal{U}_{\text{att}}$/$\mathcal{U}_{\text{opt}}$ 是指令 $u$ 中的属性集与选项集，$\mathcal{Y}_{\text{att}}$/$\mathcal{Y}_{\text{opt}}$ 是所选商品 $y$ 的属性与选项，$u_{\text{price}}$ 为指令价、$y_{\text{price}}$ 为商品价；$f_{\text{type}}=\text{TextMatch}(\bar y,\bar y^*)$ 用来在"属性选项都像但品类明显不同"时压低分数。整体进度取搜索页、商品描述页、下单确认页三个页面分的平均——**这是把一条轨迹切成三个阶段各打一次分**，所以中途换商品会拉低均值而不会清零。

**WebArena**（[附录·WebArena 进度](papers/Agent规划/2401.13178/2401.13178.pdf)）：URL 由 `util.parse` 拆成 domain/query/params，$r_d\in\{0,1\}$ 只判域名对不对，$r_q$ 用 LCS 度量查询串相似度，$r_p$ 用 F1 度量参数集合匹配（参数无序，故用 F1 而非 LCS），$r_c$ 为必需内容命中比例；$n$ 是目标 URL 组件数（固定 3），$m$ 是必需内容条数。权重 $n/(m+n)$ 随 $m$ 增大而衰减，含义是"内容越多，URL 正确性的重要性越低"。

### 评测流程

```mermaid
flowchart TD
    A[任务 g + 一个 one-shot 示例] --> B[构造 prompt: 目标 + 记忆 m_t]
    B --> C[LLM 生成文本动作 a_t]
    C --> D{动作可执行?}
    D -- 否 --> E[返回错误 / 列出合法动作]
    D -- 是 --> F[执行 T: s_t -> s_{t+1}]
    F --> G[反馈 o_t = f(s_t, a_t)]
    G --> H[更新 r_t = max 历史匹配分]
    H --> I{记忆超上下文?}
    I -- 是 --> J[滑动窗口裁掉最旧交互]
    I -- 否 --> K[继续]
    J --> B
    K --> B
    H --> L[轨迹 + r_T -> 分析面板]
```

流程里的两个非平凡选择：**滑动窗口**而非截断停机（被截断基线的做法是超过上下文就中止，AgentBoard 选择继续跑，从而支持长程交互）[§2.1](papers/Agent规划/2401.13178/2401.13178.pdf)；**Act-only** 而非 ReAct（消融显示 ReAct 在 GPT-3.5-Turbo 上并不稳定更好，作者归因于 thoughts 挤占本已紧张的长上下文预算）[附录·Ablation Study](papers/Agent规划/2401.13178/2401.13178.pdf)。

9 个环境覆盖 4 个场景：Embodied（ALFWorld / ScienceWorld / BabyAI）、Game（Jericho / PDDL）、Web（WebShop / WebArena）、Tool（Tool-Query / Tool-Operation）[§3.1](papers/Agent规划/2401.13178/2401.13178.pdf)。规模、轮数、动作空间与平均 subgoal 数：

标注流程是"改环境以适配指标"，而不只是"给指标打标签"：为让每个目标只对应**唯一**一条 subgoal 序列，作者改写了 ALFWorld/BabyAI/ScienceWorld 的部分题面（例如把"vaporize liquid"改成"vaporize liquid with a stove"），受影响题目 <5% [附录·唯一 subgoal 序列适配](papers/Agent规划/2401.13178/2401.13178.pdf)。作者强调唯一 subgoal 序列 ≠ 唯一推理路径，绕路仍可完成同一 subgoal 集 [附录·唯一 subgoal 序列适配](papers/Agent规划/2401.13178/2401.13178.pdf)。

质检三轮：自检 → 两位标注者抽样 5–10 题算错误率 → 一位熟悉全部任务者再抽检 [附录·Data Quality Control](papers/Agent规划/2401.13178/2401.13178.pdf)。第二轮错误率：ALFWorld 10.0%、BabyAI 4.2%、Jericho 25%、PDDL 5%、其余 0% [数据质量表](papers/Agent规划/2401.13178/2401.13178.pdf)。**Jericho 的 25% 是最该被记住的数字**——恰是 subgoal 语义最模糊、最依赖世界模型的环境。

指标本身的效度用人类评分校验：8 个任务各 60 条轨迹（GPT-4 / GPT-3.5-Turbo / DeepSeek-67b 生成），4 位作者在 {0, 25, 50, 75, 100}% 五档上盲评，取均值后与自动进度率做 Pearson 相关 [§3.2](papers/Agent规划/2401.13178/2401.13178.pdf)。结论是**所有任务 Pearson > 0.95**，评分者间 Fleiss' $\kappa$ 为"substantial agreement" [§3.2](papers/Agent规划/2401.13178/2401.13178.pdf)；$\kappa$ 的具体数值只出现在 [Figure 3](papers/Agent规划/2401.13178/2401.13178.pdf) 图内，正文未给数，未能从 TeX 正文核实。

- **WebShop 是"地板高、天花板也高"**：连 Llama2-70b 都有 53.6/13.1，GPT-4 76.5/39.0；WebArena 则从 39.4/15.1（GPT-4）断崖到个位数。同为 Web 场景，两任务的动作空间只有 2 vs 12，说明**动作空间宽度比环境真实感更能预测难度**。
- **Tool 场景出现"高分低成功率"现象**：TQ 上多数模型进度 50–70% 而成功率 0–48%。论文正式正文对该现象未给出解释；TeX 源码中被注释掉的草稿段落曾给出"开源模型会用工具但不擅汇总信息、交付最终结果"的说法，**属于未发表文本，不能当作论文结论引用**。

三组可核对的对照被论文自己点出：

- **分辨率论证**：Llama2-13b 与 Mistral-7b 成功率 2.1% vs 3.9%（几乎不可分），进度率 18.9% vs 24.6%（可区分）[§4.2](papers/Agent规划/2401.13178/2401.13178.pdf)。
- **一致性论证**：Text-Davinci-003 比 Llama2-70b 成功率高出 11.7 个点，进度率也高出 13.4 个点，说明两者在大差距模型上不矛盾 [§4.2](papers/Agent规划/2401.13178/2401.13178.pdf)。
- **反例/解耦案例**：CodeLlama-34b 因常不生成 `finish` 动作而成功率偏低、进度率偏高（30.0/7.6 vs CodeLlama-13b 的 25.8/10.0），作者据此称进度率更不受 agent 特有怪癖影响 [§4.2](papers/Agent规划/2401.13178/2401.13178.pdf)。这条论证同时暴露了进度率的一个软肋：它对"收尾能力"不敏感。

分析维度侧的结果：grounding accuracy（合法动作占比）GPT-4 平均 85.6%，Text-Davinci-003 仅 58.9% 但主结果不弱，Vicuna-13b-16k 68.7% 却主结果很差 → 作者结论是"会生成可执行动作 ≠ 会做任务"，也解释了纯 instruction tuning 为何提不动 agent 能力 [§4.3](papers/Agent规划/2401.13178/2401.13178.pdf) [grounding 表](papers/Agent规划/2401.13178/2401.13178.pdf)。长程交互上，开源模型除 Llama3-70b、DeepSeek-67b 外约 6 步后停止进步，GPT-4/Claude2 在 ALF 与 PDDL 上 30 步仍在涨，在 WebArena/Tool 上早早饱和 [§4.3](papers/Agent规划/2401.13178/2401.13178.pdf)。子技能雷达图（memory / planning / world modeling / self-reflection / grounding / spatial navigation）的**权重是人工设定的 1–3 分制查表**，不是学出来的 [子技能表](papers/Agent规划/2401.13178/2401.13178.pdf)——这一点在解读雷达图时应扣分。

### 可视化面板案例

第 5 节把 WandB 面板当作"分析流程"本身来演示：以 GPT-4 为 current run、6 个模型为 baseline，先看 summary 面板（总体指标 + 6 维子技能雷达图），发现 GPT-4 在 Jericho 与 WebArena 最弱，再进任务面板看 hard/easy 分解，最后下钻到 predictions 表逐条读轨迹 [§5](papers/Agent规划/2401.13178/2401.13178.pdf)。给出的具体失败案例是 Jericho 的 `zenon`：Agent 成功打开牢门却没能引开守卫，作者归因为"没有探索房间里的道具" [§5](papers/Agent规划/2401.13178/2401.13178.pdf)。这一节的价值不在案例本身，而在于它示范了 **benchmark 应交付"诊断路径"而不只是"排名"**——这也正是 BalatroEval 用 Trace 做分析单位的同一种直觉。

## 阅读重点

### 1. Progress Rate 如何定义？

定义在两个层次上：**状态匹配函数** $f(\cdot,g)\to[0,1]$ 度量当前状态与目标的相似度，**进度率**是对历史所有状态取最大值 [§2.2](papers/Agent规划/2401.13178/2401.13178.pdf)。连续可比的场景用 $r^{\text{match}}=\max_{i\le t}f(s_i,g)$；中间状态语义模糊的场景把目标分解为 $K$ 个 subgoal，用二值正则命中率的算术平均再取历史最大，即 $r^{\text{subgoal}}=\max_{i\le t}\frac{1}{K}\sum_k f(s_i,g_k)$。取值范围 $[0,1]$，初值 0，完成时 1；成功率即 $r_T=1$ 的比例。三个必须注意的性质：(a) 对 $t$ **单调不减**，因此是"最好成绩"而非"当前状态质量"；(b) 分母 $K$ 由人工标注决定，故不同任务的 $r$ 不可直接比大小，只能同任务内比模型；(c) 子目标版本的 $f$ 是 0/1，粒度被 $K$ 硬性量化（平均 3–6 个 subgoal），所以一个任务最多只有 3–6 个可区分的进度档位——这是"细粒度"这个词的真实分辨率上限。

### 2. 过程进度与最终成功率有什么区别？

不是"另一个指标"，而是**同一指标的不同截断**：成功率 = $\mathbf{1}[r_T=1]$ [任务统计表](papers/Agent规划/2401.13178/2401.13178.pdf)。区别体现在三处。第一，**分辨率**：成功率在困难任务上退化为 0/1 常数，进度率保留梯度，Llama2-13b 与 Mistral-7b 的例子就是全部论据 [§4.2](papers/Agent规划/2401.13178/2401.13178.pdf)。第二，**对过程形状的敏感性**：进度率是轨迹泛函（对 $\{s_i\}$ 取 max），成功率只看终点，所以"绕路但到达"与"直达"同分，而"早走对后崩"与"从未走对"不同分。第三，**偏差方向不同**：成功率奖励"会收尾"（CodeLlama-34b 不生成 `finish` 就被罚），进度率奖励"曾经接近过"，对收尾动作缺失、对无效动作堆积都不敏感。二者因此可以系统性背离，CodeLlama-34b/13b 那一对就是实例。

### 3. 进度信号依赖哪些标注或任务分解假设？

四层依赖，逐层都会注入偏差：

1. **subgoal 分解本身**：$K$ 个 subgoal 的切分粒度与顺序由人工给定，$r^{\text{subgoal}}$ 的档位数就等于 $K$；切粗了分辨率低，切细了标注噪声大。
2. **唯一 subgoal 序列假设**：为保证 $r_t$ 有定义，作者改写题面使每个目标只对应一条 subgoal 序列（<5% 题目被改）[附录·唯一 subgoal 序列适配](papers/Agent规划/2401.13178/2401.13178.pdf)。这是一个**任务层面的简化**，与"允许绕路"并不冲突，但确实剔除了"多解任务"（如 ScienceWorld 里用炉子或高炉都能汽化液体）。
3. **正则表达式的脆弱性**：$f(s_i,g_k)$ 靠观测定点文本的正则命中判定，环境措辞一变即失效；这也解释了为什么必须"改环境去适配指标"而不是相反 [附录·唯一 subgoal 序列适配](papers/Agent规划/2401.13178/2401.13178.pdf)。
4. **人工校验的盲区**：人类效度检验的相关系数 >0.95，但人类评分只有 5 档（0/25/50/75/100%），而自动分数是连续的——**用 5 档标签去验证一个连续量，天然会高估一致性**（分档把分歧吸收掉了）。同时第二轮标注错误率 Jericho 达 25% [数据质量表](papers/Agent规划/2401.13178/2401.13178.pdf)，说明"subgoal 是否必要且唯一"在最开放的世界模型型任务上并不稳固。$\kappa$ 具体数值正文未给，未能从原文核实。

## 与 BalatroEval 的连接

BalatroEval 的设定是：确定性可重放环境、每步动作集可枚举、可计算局部 Oracle、以决策 Trace 为分析单位、控制搜索预算、并区分"估计型过程指标"与"可枚举 Oracle 指标"。AgentBoard 正好是这套设计的**对照面**，可以逐项映射：

| 维度 | AgentBoard | BalatroEval |
|---|---|---|
| 环境确定性 | 是（$\mathcal{T}$ 确定），随机性只在采样 [§2.1](papers/Agent规划/2401.13178/2401.13178.pdf) | 是，且要求可重放 |
| 动作可枚举性 | 部分：help 动作可列出合法动作，但 WebArena 达 12 类、Jericho 达 150 个动作 | 每步动作集完全可枚举 |
| 过程指标来源 | 人工 subgoal + 正则（估计型） | 局部 Oracle 判定最优/可接受（可枚举型） |
| 分辨率上限 | 由 $K\approx3\text{–}6$ 决定 | 由每步动作数 × 步数决定 |
| 分析单位 | 轨迹 + 面板可视化 + 子技能查表 | Trace（Thought/Action/Observation/快照/分数） |

具体可借与需改的地方：

- **可直接借用的**：$r_t$ 的 $\max$ 语义（进度不回退）与"成功率 = 进度=1"的嵌套定义。BalatroEval 若同时报"到达第几底注/第几回合"的进度与"是否通关"的成功率，两者关系应与 AgentBoard 一致，避免出现两套互不兼容的口径。
- **必须替换的**：AgentBoard 的进度是**人工估计**，其效度靠人类 5 档盲评背书；BalatroEval 的优势是可以对每个状态 $s_t$ 与动作集 $\mathcal{A}(s_t)$ 计算局部 Oracle，得到"该步是否最优/可接受"的可枚举标签。因此 BalatroEval 不应模仿 subgoal-正则路线，而应把 AgentBoard 的 $r_t$ 当作**下界型基线指标**：当 Oracle 说"这步是次优"而 $r_t$ 仍在上涨时，正是估计型指标失效的证据。
- **预算控制的差异**：AgentBoard 用固定 agent 骨架 + 滑动窗口 + Act-only 来控制框架差异 [§2.1](papers/Agent规划/2401.13178/2401.13178.pdf)，但**没有控制推理预算**（无 thinking token 上限、无搜索预算归一）。BalatroEval 的"控制搜索预算"是它相对 AgentBoard 的方法论增量，可在论文中作为对 AgentBoard 式评测的明确改进点。
- **可批判的继承**：AgentBoard 的 6 个子技能分是查表权重 [子技能表](papers/Agent规划/2401.13178/2401.13178.pdf)，BalatroEval 若要报"决策质量"维度，应改用可计算的量（如每步 regret = Oracle 最优值 − 实际动作值），而不是人工权重表。

## 局限与可批判点

**作者自述的局限**（[§7](papers/Agent规划/2401.13178/2401.13178.pdf) Limitations 段）：依赖人工标注 subgoal；曾考虑用 LLM 标注但当前模型在 AgentBoard 任务上表现太差、无法生成可靠 subgoal；评测局限于模拟环境，真实世界评测受"真值标签可变"与安全风险制约。

**我认为更值得追问的**：

1. **分辨率被 $K$ 卡死**，而论文把"fine-grained"当作核心卖点。3–6 个档位对"增量进步"的宣称是紧的；论文自己也承认，标注错误率最高的 Jericho（25%）恰好是 subgoal 最多的任务之一（平均 6 个）。
2. **进度率对"无效动作"零惩罚**。$r_t$ 只看 max 匹配分，一个反复撞墙但曾打开过冰箱的 Agent 与一个高效完成的 Agent 在同一 $r$ 上不可区分。这与 BalatroEval 想测的"决策质量"是正交的。
3. **effort/预算未归一**。同一 $r$ 可能花 6 步也可能花 30 步，论文的长程分析展示了这条曲线，但没有把它做成指标（如 AUC of $r_t$ over $t$，或达到 $r=0.75$ 所需步数）。这是"过程指标"最容易补的一刀。
4. **主观维度伪装成客观维度**。子技能雷达图的权重表是人工赋值 1–3 分，却以"capability scores"呈现，读者容易误读为测量结果 [子技能表](papers/Agent规划/2401.13178/2401.13178.pdf)。
5. **人类效度检验的循环性**：标注者既定义了 subgoal，又作为评分者验证由该 subgoal 算出的分数，>0.95 的相关性部分来自同源假设。
6. **可复现性摩擦**：正文 1013 环境 vs 表格 1012 的算术不一致；$\kappa$ 数值只在图里；单任务步数上限未在正文给出。这些都不影响结论方向，但影响复刻。

## 开放问题

- 进度率能否**自动**获得而不靠人工 subgoal？论文说 LLM 标注当前不可行 [§7](papers/Agent规划/2401.13178/2401.13178.pdf)，但在有确定性状态与可枚举动作的环境（如 Balatro）里，Oracle 可以替代标注——这条路线 AgentBoard 没走。
- 如何把"步数/预算"并入进度定义，得到对效率敏感的单一标量（$r$ 的曲线下面积？首达时间？）。
- 子目标分解的**多解性**被 <5% 的题目改写绕过了；对天然多解的任务，进度率应定义为对最优可达 subgoal 集的最大匹配还是最小值匹配？论文未讨论。
- 6 个子技能之间是否可辨识？当前用查表权重，无法从数据反推各技能贡献，也无法检验正交性。
- 长上下文能力与 agent 能力的关系：GPT-3.5-Turbo-16k 并不优于 4k 版本（平均 34.2/13.6 vs 41.4/19.7）[主结果表](papers/Agent规划/2401.13178/2401.13178.pdf)，这与"窗口越大越好"的直觉相反，机制未解释。
