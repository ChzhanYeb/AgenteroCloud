**版本：** 2026-11-15  
**使用目标：** 支撑 2026 年 12 月开始投递大模型评测、Benchmark 建设、评测框架/自动化研发实习。  
**依据：** 用户提供的《面向长程决策 Agent 的可验证评测与失败归因》调研报告（v3.0 决策更新，2026-11-13）、BalatroEval 项目设计资料，以及 2026-11-15 制定的实习准备任务清单。

---

# 0. 怎么使用这份清单

这不是“把 111 篇文献全部读完”的任务。目标是把已有调研报告从“资料收集”变成“能支撑项目设计、实验选择和面试讨论的知识体系”。

## 0.1 阅读优先级

- **P0｜精读：** 必须理解问题定义、方法、实验、局限，并能解释它对项目设计的影响。
- **P1｜重点阅读：** 读摘要、方法、核心图表、实验结论和局限；必要时回看全文。
- **P2｜定向查阅：** 先读摘要和项目文档，遇到具体设计问题再深入。
- **P3｜暂缓：** 本阶段只保留索引，不投入系统阅读时间。

## 0.2 每篇材料的完成标准

不要把“打开过论文”标记为完成。至少留下以下记录：

- [ ] 研究问题：作者试图解决什么问题？
- [ ] 评测对象：Base Model、Post-trained Model、Agent、Judge、推理系统，还是训练算法？
- [ ] 方法：输入、执行协议、核心算法/判定器是什么？
- [ ] 指标：主指标是什么？计算单位是样本、动作、轨迹还是任务？
- [ ] 实验：对比了哪些基线？样本规模和控制变量是什么？
- [ ] 主要结论：哪条结论有数据支持？
- [ ] 局限：数据污染、评审偏差、环境差异、统计功效、成本或外部效度问题是什么？
- [ ] 对 BalatroEval / 求职岗位的启发：具体影响哪项设计或技术决策？

**每篇精读论文控制在一页笔记以内。** 重点论文可扩展到两页，其他论文不要做长篇摘抄。

## 0.3 总体阅读顺序

1. **先读自己的项目：** 确定项目实际做了什么、尚未做什么，避免文献阅读与当前实现脱节。
2. **再读评测基础：** 了解 Benchmark、评测对象、指标、统计和效度。
3. **再读 Agent 规划与轨迹评测：** 支撑 BalatroEval 的能力定义和错误归因。
4. **再读 Balatro 生态：** 明确差异化、复用边界、真实游戏对齐和许可风险。
5. **并行读 vLLM：** 沿请求链路阅读架构和实验，不做全仓库漫游。
6. **最后读可解释性：** 从行为分析进入内部机制，严格区分证据层级。

# 2. 文献主线 A：Agent 规划、多步决策与长程能力

**对应岗位：** 基模评测、Agent 评测、长程任务 Benchmark。  
**对应项目：** BalatroEval 的能力定义、任务环境、跨步决策、状态跟踪和资源规划。

## 2.1 P0 精读

### 1. ReAct — Synergizing Reasoning and Acting in Language Models
- 链接：https://arxiv.org/abs/2210.03629
- 阅读重点：
  - Thought–Action–Observation 循环如何定义 Agent 交互？
  - Trace 为什么成为过程分析的基本单位？
  - 环境反馈如何约束下一步决策？
- 项目连接：定义 BalatroEval 的决策 Trace 结构。

### 2. Tree of Thoughts — Deliberate Problem Solving with LLMs
- 链接：https://arxiv.org/abs/2305.10601
- 阅读重点：
  - 从 token 级生成转向 thought 级搜索的机制。
  - 搜索依赖哪些状态评估与回溯能力？
  - Game of 24 的成功率提升说明了什么，又不能说明什么？
- 项目连接：理解测试时搜索与局部 Oracle 的区别。不要把 Oracle 当成模型规划器。

### 3. LATS — Language Agent Tree Search
- 链接：https://arxiv.org/abs/2310.04406
- 阅读重点：
  - MCTS、价值估计、语言模型反思如何组合？
  - 环境可回滚和状态可重放为什么重要？
  - 搜索成本如何影响 Agent 评测？
- 项目连接：为“环境是否支持重放”和“搜索能力是否公平比较”提供背景。

### 4. LLMs Can't Plan, But Can Help Planning in LLM-Modulo Frameworks
- 链接：https://arxiv.org/abs/2402.01817
- 阅读重点：
  - LLM 生成候选计划与外部验证器之间如何分工？
  - 规划、执行和验证分别由谁负责？
  - 哪些错误可以由外部符号验证器捕获？
- 项目连接：支撑“模型负责提出动作，环境负责判定”的设计原则。

### 5. AgentBench — Evaluating LLMs as Agents
- 链接：https://arxiv.org/abs/2308.03688
- 阅读重点：
  - 多环境评测如何组织？
  - 任务成功率、环境差异和模型能力之间是什么关系？
  - 长程任务的错误累积如何体现？
- 项目连接：对照 BalatroEval 与通用 Agent Benchmark 的差异。

### 6. AgentBoard — An Analytical Evaluation Board of Multi-turn LLM Agents
- 链接：https://arxiv.org/abs/2401.13178
- 阅读重点：
  - Progress Rate 如何定义？
  - 过程进度与最终成功率有什么区别？
  - 进度信号依赖哪些标注或任务分解假设？
- 项目连接：比较估计型过程指标与可枚举局部 Oracle 指标。

### 7. BALROG — Benchmarking Agentic LLM and VLM Reasoning on Games
- 链接：https://arxiv.org/abs/2411.13543
- 阅读重点：
  - 多游戏环境如何统一接口和报告？
  - Progress / Score 的归一化方式是什么？
  - 视觉观察、工具交互和游戏策略分别带来什么困难？
- 项目连接：最重要的游戏 Agent Benchmark 对照之一。

# 3. 文献主线 B：模型评测体系、Judge、统计与评测效度

**对应岗位：** 基模评测方向是核心；预训练评测研发的 Benchmark 方向也需要。  
**对应项目：** 指标定义、配对实验、自动判分、结果可信度和报告规范。

## 3.1 P0 精读

### 1. HELM — Holistic Evaluation of Language Models
- 链接：https://arxiv.org/abs/2211.09110
- 重点：多场景、多指标、统一协议、透明报告。
- 产出：一张“评测维度 × 指标 × 场景”的框架图。

### 2. BIG-bench — Beyond the Imitation Game
- 链接：https://arxiv.org/abs/2206.04615
- 重点：任务集合如何构建；任务多样性与能力曲线；任务难度和饱和问题。
- 产出：总结大规模 Benchmark 的覆盖优势和聚合分数风险。

### 3. AI Agents That Matter
- 链接：https://arxiv.org/abs/2407.01502
- 重点：准确率之外的成本、可复现性、数据污染和评测协议。
- 产出：BalatroEval 应报告哪些成本和运行信息。

### 4. Adding Error Bars to Evals
- 链接：https://arxiv.org/abs/2411.00640
- 重点：评测结果的抽样不确定性；置信区间；模型差异的统计解释。
- 产出：为 BalatroEval 写统计分析方案。

### 5. Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena
- 链接：https://arxiv.org/abs/2306.05685
- 重点：Judge 与人工偏好的一致性、位置偏差、长度偏差、自我增强偏差。
- 产出：Judge 风险清单。

### 6. G-Eval
- 链接：https://arxiv.org/abs/2303.16634
- 重点：基于 rubric 的模型评审流程、评分提示和一致性。
- 产出：了解 Judge Pipeline，但不将其作为 BalatroEval 主判分器。

### 7. JudgeBench
- 链接：https://arxiv.org/abs/2410.12784
- 重点：客观正确性判断与偏好判断的差异；Judge 能力如何被独立测量。
- 产出：明确哪些任务必须使用确定性判定器。

### 8. AgentRewardBench
- 链接：https://arxiv.org/abs/2504.08942
- 重点：自动评估 Agent Trace 的可靠性；不同裁判在不同基准上的表现差异。
- 产出：把“评测器本身也要评测”纳入框架。

### 9. Trust or Escalate
- 链接：https://arxiv.org/abs/2407.18370
- 重点：Judge 置信度、选择性评估、弃权与人工升级。
- 产出：理解 F0“证据不足”和弃权机制的设计价值。

## 3.3 P0：统计方法与实验设计专题

这些内容不必全部依赖论文，重点是掌握适用条件和如何解释结果。

- [ ] Accuracy / Exact Match：适合什么类型的确定答案？
- [ ] pass@k：代码生成中估计的是什么？与多次任务成功率有什么区别？
- [ ] pass^k：为什么强调多次运行全部成功？如何避免与 pass@k 混淆？
- [ ] Pairwise Win Rate：平局、顺序偏差和比较单位如何处理？
- [ ] Task Success Rate：Agent 任务成功的终态判定如何定义？
- [ ] Bootstrap CI：抽样单位是什么？按样本还是按任务/场景重采样？
- [ ] McNemar：为什么适合配对二分类结果？
- [ ] Wilcoxon Signed-Rank：适用于什么配对连续/序数差异？需要注意什么假设？
- [ ] Holm：多重假设检验为什么需要校正？
- [ ] Cohen's κ：类别不平衡时如何解释？为什么要看 per-class 和混淆矩阵？
- [ ] Effect Size：不能只看 p 值，如何报告实际差异？
- [ ] Power Analysis：样本规模不足时，如何降低结论强度？

## 3.4 Benchmark 数据工程专题（岗位二）

- [ ] Hugging Face Datasets：Dataset / DatasetDict、map、filter、streaming、cache。
- [ ] JSONL / Parquet：适用场景、schema、读写和版本化。
- [ ] 数据质量：去重、缺失值、异常值、标签一致性、数据泄漏。
- [ ] 污染检测：精确匹配、模糊匹配、语义改写风险、时间切分。
- [ ] 数据版本：固定版本号、数据 hash、变更日志、可追溯来源。
- [ ] Train / Dev / Test / Holdout：隔离原则和防止反复调参泄漏。
- [ ] Benchmark Adapter：统一样本格式、任务输入输出和评分接口。
- [ ] Checkpoint Evaluation：跨 checkpoint 评测、能力变化曲线和退化告警。

## 4.1 P0 精读

### 1. Who&When — Which Agent Causes Task Failures and When?
- 链接：https://arxiv.org/abs/2505.00212
- 重点：Agent 级和步骤级归因任务如何定义；为什么自动定位准确率低？
- 产出：解释“让 LLM 读 Trace 自动找根因”的能力边界。

### 2. TRAIL — Trace Reasoning and Agentic Issue Localization
- 链接：https://arxiv.org/abs/2505.08638
- 重点：Trace 错误分类、人工标注数据、自动定位性能。
- 产出：对照 BalatroEval 的步骤级错误证据。

### 3. MAST — Why Do Multi-Agent LLM Systems Fail?
- 链接：https://arxiv.org/abs/2503.13657
- 重点：失败模式分类学、标注一致性、类别定义。
- 产出：学习如何把错误分类做成可操作标签，而不是宽泛描述。

### 4. AgentDebug
- 链接：https://icml.cc/virtual/2026/77923
- 重点：模块化错误分类、根因隔离、纠正反馈。
- 产出：思考 F 类标签与可修复错误之间的映射。

### 5. The Hallucination Snowball
- 链接：https://arxiv.org/abs/2608.14588
- 重点：错误如何沿多步/多 Agent 流水线传播；边界检查如何截断传播。
- 产出：把“首次失败步”和“错误传播”加入 Trace 分析。

## 4.3 必须形成的归因概念区分

- [ ] **结果评测：** 任务最终是否成功？
- [ ] **过程评测：** 中间状态是否按预期推进？
- [ ] **行为诊断：** Agent 在哪一步做了什么错误动作？
- [ ] **根因归因：** 哪个错误机制导致后续失败？
- [ ] **因果解释：** 如果干预某个内部/外部因素，行为是否改变？

不要把这五层混为一谈。BalatroEval 的确定性重放能增强行为诊断的可验证性，但不自动等于对模型内部因果机制的解释。
